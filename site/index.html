Le constat

Un agent IA a besoin d'un vrai poste de travail

Pour être utile, un agent comme Claude Code a besoin du code, des outils, des clés, et d'une machine où travailler longtemps. Aujourd'hui, chaque équipe bricole sa propre solution.

Une machine à préparer pour chacun

Cloner les dépôts, installer les outils, distribuer les clés : des heures par personne et par projet, à refaire à chaque arrivée.

Le code qui part chez un fournisseur

Les postes et les agents hébergés chez un éditeur font sortir le code, les secrets et les conversations de l'organisation.

SSH, un outil d'initiés

Clés, configuration, éditeur distant : un frein pour qui n'est pas développeur, et impraticable depuis un téléphone.

Plusieurs agents, aucune vue d'ensemble

Un agent attend une réponse, un autre a fini depuis une heure : sans vue d'ensemble, le temps se perd entre les fenêtres.

La solution

Trois briques, une seule chaîne

Trois logiciels développés au CATIE, chacun utile seul, conçus pour fonctionner ensemble. Plati crée les machines, SSHX en ouvre une dans le navigateur, SSHX Platform les réunit toutes.

Créer

Plati

Le micro-cloud de l'équipe : des micro-VMs sur les serveurs de l'organisation, créées à partir de modèles de projet.

  • Micro-VMs Incus créées, copiées ou transférées en quelques clics
  • Modèles de projet : image, dépôts, agent IA, skills, outils
  • Comptes (mot de passe ou Entra ID), clés SSH, accès Git selon le niveau
  • Secrets chiffrés, injectés dans les machines
  • Espace personnel conservé, ressources plafonnées, arrêt automatique

SSHX

Une machine dans le navigateur : le terminal partagé par un simple lien, chiffré de bout en bout, outillé pour suivre un agent IA.

  • Un lien suffit : ni compte, ni clé, ni port ouvert
  • Le serveur relaie les terminaux sans pouvoir les lire
  • Canevas collaboratif : curseurs, chat, partage d'écran
  • Suivi de Claude Code, cartes de fichiers, VS Code intégré
  • Utilisable sur téléphone, mise à jour automatique

SSHX Platform

Le poste de travail de chacun : tous les terminaux de toutes ses machines, avec l'état de ses agents IA, dans une seule page.

  • États des agents : au travail, question, autorisation, terminé
  • Notifications, compteur « à traiter », version mobile

Le parcours

De la clé SSH à la démo, en sept étapes

L'administrateur prépare une fois ; ensuite, l'équipe travaille.

  1. 1
    AdministrateurPlati

    Rassembler les clés

    L'administrateur collecte les clés SSH publiques de chaque personne et les enregistre dans Plati. Elles sont installées dans toutes ses machines, y compris celles déjà démarrées.

    Il attribue aussi à chacun une clé Git qui correspond à son niveau : c'est elle qui décide des dépôts que ses machines peuvent atteindre.

  2. 2
    AdministrateurPlati

    Décrire chaque projet une fois

    Un modèle réunit l'image, les dépôts à cloner, l'agent IA et ses skills, les ressources, et des briques réutilisables : SSHX, Tailscale, Docker, VS Code.

    Changer d'agent ou de fournisseur d'IA pour toute l'équipe revient à modifier le modèle, puis à reconstruire les machines.

  3. 3
    AdministrateurPlati

    Créer les micro-VMs

    Plati crée une micro-VM par personne et par projet sur le serveur de l'organisation, avec Claude Code, SSHX et Tailscale déjà installés. Chacune rejoint le réseau privé.

    L'espace personnel survit aux reconstructions. Une machine qui fonctionne se copie, ou se transfère à la personne à qui elle est destinée. Les machines s'arrêtent seules après un délai.

  4. 4
    AdministrateurSSHX Platform

    Relier chaque machine à SSHX Platform

    Une seule commande, lancée dans la machine : sshx platform enroll <adresse> <jeton> && sshx. La machine apparaît dans SSHX Platform et les hooks de Claude Code sont installés : l'état de chaque agent remonte, terminal par terminal.

    La clé de la machine naît dans le navigateur de l'administrateur. Les serveurs ne reçoivent que des données chiffrées.

  5. 5
    UtilisateurAdministrateurSSHX Platform

    Se connecter, recevoir ses machines

    L'utilisateur se connecte avec son compte Microsoft, puis choisit une phrase secrète qui ne quitte jamais son navigateur. L'administrateur lui partage ses machines : leur clé est chiffrée pour lui.

    Pas d'éditeur à installer, pas de clé SSH à manipuler.

  6. 6
    UtilisateurSSHX Platform

    Travailler avec l'agent, de partout

    Tous les terminaux sont dans une liste, groupés par projet ; un terminal s'ouvre en plein écran, et le clavier suffit pour passer de l'un à l'autre.

    Quand Claude Code pose une question, demande une autorisation ou termine, la ligne change de couleur et le navigateur prévient. Un raccourci mène au prochain terminal à traiter. La même liste est disponible sur téléphone.

  7. 7
    UtilisateurTailscaleSSHX

    Montrer l'avancée, sans rien publier

    L'application en cours tourne dans la machine et s'ouvre à son adresse du réseau privé : les collègues suivent les progrès, Internet ne voit rien.

    Pour travailler à deux, un lien SSHX partage le terminal en direct, curseurs compris.

SSHX Platform

Une alternative à VS Code ou Claude Desktop pour coder à distance

Les agents travaillent sur les machines de l'organisation. SSHX Platform est la fenêtre qui permet de les piloter, depuis n'importe quel navigateur du réseau privé.

  • Un navigateur suffitNi éditeur, ni extension, ni configuration SSH. Un ordinateur prêté ou un téléphone font l'affaire.
  • Toutes ses machines dans une listeTerminaux groupés par projet, épinglés, renommés, triés : chacun organise les siens, même sur une machine partagée.
  • Les agents d'un coup d'œilAu travail, question, autorisation, terminé : l'état vient des hooks de Claude Code, terminal par terminal.
  • Pensé pour le clavierDes raccourcis qui suivent la disposition du clavier (AZERTY, BÉPO…), ne sont jamais envoyés au shell et se redéfinissent.
  • VS Code quand il le faut« Ouvrir dans VS Code » ouvre le dossier du terminal dans un éditeur complet, dans le navigateur.

Pour coder sur une machine distante

Il faut
  • Un navigateur récent
  • Un compte Microsoft de l'organisation
  • Tailscale sur l'appareil, pour rejoindre le réseau privé
Il ne faut plus
  • Installer un éditeur ou des extensions
  • Configurer SSH, gérer des clés
  • Copier le code sur son poste
  • Garder une fenêtre ouverte par machine
Sécurité

La sécurité en couches, limites comprises

Chaque couche réduit ce que la suivante doit protéger. Et ce qui reste visible est dit clairement.

Sur votre matériel

Les micro-VMs tournent sous Incus, sur les serveurs de l'organisation. Aucune machine chez un fournisseur de cloud.

Dans votre réseau privé

Plati, SSHX Platform, les machines et les démos ne sont joignables que par Tailscale. Rien n'est exposé sur Internet.

Avec vos comptes

Connexion par Microsoft Entra ID. Les administrateurs décident qui a un compte, et qui administre.

Une machine par personne et par projet

Un agent n'atteint que ce que sa machine atteint : ses dépôts, ses secrets, rien d'autre.

Des droits au plus juste

Accès Git selon le niveau de chacun, secrets chiffrés (AES-256-GCM) injectés dans les machines, ressources plafonnées.

Chiffrement de bout en bout

Contenu des terminaux, dossiers, branches et questions des agents sont chiffrés dans la machine et déchiffrés dans le navigateur. Les serveurs n'en voient rien.

Ce qu'il faut savoir

  • L'administrateur qui relie une machine à SSHX Platform en détient la clé : il peut ouvrir ses terminaux. C'est le choix d'un service géré.
  • Les serveurs voient les noms des machines et des sessions, l'état des agents et les horodatages : de quoi afficher la liste, pas le travail.
  • « Ouvrir dans VS Code » passe par le relais SSHX sans chiffrement de bout en bout ; le trafic reste chiffré par Tailscale.

  • Plusieurs organisations sur une même installation
